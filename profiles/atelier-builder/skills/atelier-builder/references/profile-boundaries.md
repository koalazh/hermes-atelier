# Profile boundary rubric

Split only when at least one of these is concrete and material:

- different tool or data permission;
- different durable Memory or knowledge ownership;
- different working directory or execution isolation;
- different model or resource requirement;
- failure isolation;
- independent evolution or reuse by multiple entries;
- context isolation with a plausible quality benefit.

For a requested demonstration, label business-essential and demonstration-only boundaries separately and include the simpler single-Profile version.

An allowlist is a security boundary. It is not a route, preference, sequence, fallback, or orchestration graph.
